# Тренажёр «Замер температуры говядины»

Электронный тренажёр на дизайн-системе **KU** (`kuds-ds`). Собран по сценарию
методиста `input/тренажер-замер говядины (1).docx` и материалам из `input/`.

- **ЦА:** Обучение МС, направление «Продукты» (`data-audience="ms" data-direction="produkty"`)
- **Длительность:** ~15 минут, 8 глав
- **SCORM 1.2** — прогресс, переменные и завершение работают из коробки
- Работает офлайн, без сборки, фреймворков и CDN

## Предпросмотр

```bash
cd courses/zamer-govyadiny
python3 -m http.server 8000
# открыть http://localhost:8000
```

## Механики

Курс использует готовые механики ДС (drag-and-drop, сортировка, модалки,
роутер глав) и добавляет свои — они лежат в `<script>` в конце `index.html`,
префикс `zb-`:

| Функция | Что делает |
|---|---|
| `zbCheck(id)` | Тест с кнопкой «Ответить»: один (`data-mode="single"`) или несколько (`multi`) вариантов; варианты могут быть текстом (`.zb-opt`) или картинками (`.zb-pick`) |
| `zbCheckSort(id)` | Последовательность шагов. По `data-correct` на списке или по `data-sort-keys` на квизе — тогда одинаковые шаги взаимозаменяемы |
| `zbCheckZones(id)` | Распределение по корзинам, `data-zones="idЗоны:ключ\|idЗоны:ключ"` |
| `zbRetry(id)` | Сброс упражнения. После ответа кнопка `[data-zb-check]` прячется; при ошибке в нижний ряд `[data-zb-after]` — под разбор — добавляется «Попробовать ещё раз» |
| `data-zb-next="idШага"` | Пошаговое раскрытие блоков внутри главы (кнопки «Продолжаем!», «Далее») |
| `data-zb-modal-on-enter` | Дисклеймер, всплывающий один раз при входе в главу |
| `data-zb-shuffle` | Перемешать варианты при загрузке («разместить хаотично» по сценарию) |

### Как править тексты

Обратная связь живёт **рядом с вопросом**, в `<template>`:

```html
<div class="zb-quiz" id="q-primer" data-mode="single" data-correct="2">
  <div class="zb-opts" data-mode="single"> … варианты с data-i="1|2|3" … </div>
  <template data-fb-ok>Текст при верном ответе</template>
  <template data-fb-bad>Текст при ошибке</template>
</div>
```

Чтобы поменять верный ответ — правь `data-correct` (номера через запятую).
JS трогать не нужно.

### Как показывается ошибка

При **верном** ответе подсвечиваются все верные варианты. При **ошибке**
красным помечается только то, что выбрал ученик, — правильный ответ не
раскрывается, чтобы «Попробовать ещё раз» имело смысл. Исключение —
задание на инвентарь: там `data-reveal="all"`, как просил сценарий
(«верные ответы обводятся в зелёную рамку, неверные в красную»).

## Заметки по вёрстке

Пара вещей, о которые легко споткнуться при правках:

- `.ku-feedback` — это **flex-контейнер**. Внутрь клади ровно два узла:
  иконку и `<span class="ku-fb-msg">` с текстом. Голые текстовые узлы
  превращаются в отдельные колонки и раскладка рассыпается.
- Заглушки графики ловят ошибку через инлайновый
  `onerror="this.removeAttribute('src')"`. Вынести это в функцию из
  `<script>` в конце body нельзя: 404 приходит раньше, чем скрипт выполнится.
- `.ku-chip` в ДС — градиентная пилюля под короткие слова. Для длинных
  описаний в главе 6 она переопределена на нейтральную карточку (`.zb-cards`).
- `.ku-exercise__label` внутри решённого упражнения получает бейдж «Решено»
  от ДС. В карточках-разборах поэтому используется свой `.zb-zoom__label`.
- Крупные варианты-картинки (`.zb-picks.l`) идут с `object-fit: contain`:
  кадрирование съедало бы именно ту деталь — угол щупа, — по которой
  ученик выбирает ответ.

## Расхождения со сценарием

Осознанные отступления, которые стоит подтвердить методисту:

1. **Опечатки исправлены:** «Вымыть руки руки» → «Вымыть руки»,
   «закончилтсь» → «закончились», «секундомнр» → «секундомер»,
   «не соответсвует» → «не соответствует», «Ситауция» → «Ситуация».
2. **Итоговое задание:** три шага «Вымыть руки» одинаковы, поэтому проверка
   сравнивает последовательность по ключам — любой из трёх экземпляров
   засчитывается на любой из трёх позиций.
3. **Дисклеймеры** («Требования к оборудованию», «Запомни!») сделаны
   модалками, как в сценарии, но с крупной вёрсткой — чтобы их было удобно
   заскринить, как просит текст задания.
4. **Картинка 11** — карточка-перевёртыш: на лицевой стороне правила для
   NIECO и DUKE текстом, на обороте схема.
5. **Кнопки** из сценария («Продолжаем!», «Далее», «Ответить», «Ситуация 2»…)
   сохранены дословно: внутри главы они раскрывают следующий блок, на границе
   главы — ведут в следующую главу.
